# SameGame - CodinGame Port

This project is a port of the tile-matching puzzle [SameGame](https://en.wikipedia.org/wiki/SameGame). The rules used here are aligned with standard benchmarks found in AI research publications.

> **Playable Version:** A human-playable version is available at [js-games.de](http://www.js-games.de/eng/games/samegame/lx/play).

---

## 🎯 The Goal

The primary objective of the game is to **maximize your score**. You achieve this by removing regions of connected cells of the same color that are as large as possible.

---

## 📜 Rules

SameGame is played on a rectangular grid filled with cells of various colors.

1. **Grid Setup & Coordinates:**
   - The game board consists of **15 rows and 15 columns**.
   - `0 0` (`column` `row`) corresponds to the **bottom-left corner**.
   - `14 14` corresponds to the **top-right corner**.
   - Colors are represented by integers: `0`, `1`, `2`, `3`, and `4`. Empty cells are marked as `-1`.

2. **Actions & Mechanics:**
   - A move consists of choosing a tile on the board by outputting its coordinates (`column` `row`).
   - **Legality:** A move is legal **only if** the selected cell has at least one cardinal neighbor (up, down, left, right) of the same color (i.e., a connected group of size $\ge 2$).
   - **Clearing:** Selecting a valid cell removes the entire connected region of the same color.
   - **Gravity (Vertical):** Remaining blocks above removed cells drop down to fill empty spaces within their column, ensuring no gaps above row `0`.
   - **Shift (Horizontal):** If a column becomes completely empty, all columns to its right slide as far left as possible to eliminate empty column gaps.

3. **Game End Conditions:**
   - **Error End:** Choosing an illegal action (e.g., selecting an empty cell or a region of size 1) results in an immediate game error.
   - **Natural End:** The game ends when no legal actions remain (i.e., tile `0 0` is empty or all remaining connected regions have size 1).

4. **Scoring System:**
   - The game score is cumulative across all turns.
   - Removing a region of $n$ cells yields a score of:
     $$\text{Score} = (n - 2)^2$$
   - **Clear Board Bonus:** Clearing the entire board (making tile `0 0` empty) awards a **1,000 point bonus**.

## 🔌 Game IO & Protocol

### Input for One Game Turn
- **First 15 lines:** Grid status from top (row `14`) to bottom (row `0`).
- **Each line:** 15 space-separated integers representing cell colors (`0`, `1`, `2`, `3`, `4`, or `-1` for empty).

### Output for One Game Turn
- **Format:** A single line with two space-separated integers `column` `row`, optionally followed by a debug message.
- **Example:** `0 1 this is optional message`

### Constraints
- **First turn response time:** $\le 20\text{ s}$
- **Turn response time:** $\le 50\text{ ms}$

## 🚀 How to Run

### Prerequisites
- **Rust** (stable toolchain, edition 2021) with `cargo`.
- **SQLite**: `rusqlite` is not built with the `bundled` feature, so the SQLite library must be available at link time (`sqlite3.lib` at the project root on Windows, or via vcpkg) and `sqlite3.dll` must be reachable at runtime (e.g. in `PATH`).
- **Python 3** (standard library only) to export results with `get_result.py`.

### Testcases & puzzle hash
Each file in `testcases/` is a CodinGame testcase exported as JSON: its title (`title`), the grid (`testIn`), the `isTest`/`isValidator` flags, and a `hash` field.

The CodinGame validator contains **every grid twice**: `Standard Testset N` and `Standard Testset N (recolored)`. The two versions have the same layout with the colors swapped, so the **same sequence of actions** solves both and gives the same score.

The `hash` field is not generated by CodinGame: it was **added manually** to each JSON file, and the two versions of a grid share the same hash. This means:
- a grid only needs to be solved once: `run.bat` only lists one testcase per hash (the validation grids),
- results in the database and in the submitted JSON are grouped by `hash`, so one solution covers both versions.

> When adding a new testcase, give it the same `hash` as its recolored twin, or a new unique value if it has none.

### 1. Build
Always build in release mode: the solver is time-bounded and a debug build is much slower.
```bash
cargo build --release
```

### 2. Solve a testcase
The binary takes a single argument: the path to a testcase JSON file from `testcases/`.
```bash
# Windows
target\release\cg_samegame_rust.exe testcases\test1.json

# or through cargo
cargo run --release -- testcases/test1.json
```
- **stdout:** the sequence of actions found.
- **stderr:** the initial board and debug logs, then `Row inserted successfully!` once the result is saved.

Each run appends one row to `my_database.db` (SQLite, created automatically in the current directory), table `my_objects`:

| column    | content                                   |
|-----------|-------------------------------------------|
| `name`    | testcase title (e.g. `Standard Testset 1`) |
| `actions` | the actions found by the solver           |
| `hash`    | hash of the puzzle (from the testcase JSON) |
| `score`   | score reached                             |

> Run the binary from the project root so every run writes to the same `my_database.db`.

### 3. Solve a batch of testcases
`run.bat` runs the release binary sequentially on the validation grids, one testcase per unique hash (comment/uncomment lines with `@REM` to choose which ones):
```bat
cargo build --release
run.bat
```
Since every run is stored, you can launch it several times: only the best score per puzzle is kept at export.

### 4. Export the best solutions for CodinGame
```bash
python get_result.py > result.json
```
The script reads `my_database.db`, keeps for each puzzle `hash` the actions with the best score (only testcases whose name starts with `Standard`), and prints:
- a JSON object `{ hash: actions }` to submit on CodinGame,
- the estimated total score on the last line (`total score: ...`, doubled because each grid is played twice by the validator, see [Testcases & puzzle hash](#testcases--puzzle-hash)).

> Remove the last `total score` line from the output file before submitting the JSON.
